# Feature Specification: Persona genesis and the persona firewall

**Feature Branch**: `task-0013-persona-genesis` · **Spec dir**: `specs/013-persona-genesis`

**Created**: 2026-08-28 · **Status**: Draft

**Input**: TASK-0013 / M3 — E1 persona genesis on Opus 5 (three pre-session calls),
port of promptworld I's `persona` two-half firewall: structural impossibility
(mode-0444 write-once, no post-genesis write path) plus a model-free validator
(anchor echo + drift lexicon). Consumes decision-0003 +
docs/design/llm-routing-and-budget.md (§1.3 E1 row, §8 persona-firewall port
ruling), docs/design/kithcraft-brief.md (#5 weirdness dial, minds-are-others,
the politeness-policing spell-breaker), decision-0002 (profession × biome
variant as cast distinctiveness), docs/design/demo-build-plan.md §3.2 (M3).

## What changes vs promptworld I (the port's one real delta)

In promptworld I personas were **authored** (`persona.Texts`, `Anchors`,
`DriftMarkers` — hand-written maps). In Kithcraft they are **generated at birth**
by E1 on Opus 5 (brief #5): names, values, endogenous desires. The firewall is
unchanged by that — decision 5's demand *is* the structural half — but the
anchor line and the per-persona drift markers can no longer be authored
constants: **E1 must emit them as part of the persona**, structured, so the
model-free validator has its data. What stays authored: the **moralizing
lexicon** (cast-wide, catches the politeness-policing spell-breaker) — that one
is doctrine, not character, and is never model-generated.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - A person I did not write (Priority: P1)

As a player, I want the villagers to be people I did not write, so that their
company counts as company.

**Independent Test**: Three personas generated by E1 on Opus 5 in three
pre-session calls (card AC #1), each carrying name, values, endogenous desires,
an anchor line, and drift markers; each paired with a profession and biome
variant so the fiction and the body agree (card AC #5).

**Acceptance Scenarios**:

1. **Given** a cast of three entries (id, profession, biome variant), **When**
   genesis runs, **Then** exactly three E1 calls are made on the class's
   declared model (Opus 5 per `llm.E1`), pre-session, latency unbounded.
2. **Given** a generated persona, **Then** it records its cast pairing
   (profession + biome variant) and its content reflects it.
3. **Given** the weirdness dial, **Then** the genesis prompt pins it
   conservative (brief #5) — distinct, grounded characters, not surrealism.

### User Story 2 - Written once, then structurally untouchable (Priority: P1)

As a villager, I want my nature to be beyond everyone's reach — the model's,
the player's, the daemon's — so that who I am is not up for revision.

**Independent Test**: Card AC #2 — persona files land at mode 0444 via a
write-once path; a test from an **external package** confirms the package's
exported API offers **no post-genesis write path to attempt**, not merely that
a write fails at runtime (the M2 API-surface-test idiom).

**Acceptance Scenarios**:

1. **Given** genesis has written a persona file, **Then** the file is mode 0444
   and the writing function refuses to overwrite an existing persona.
2. **Given** the package's exported surface, **Then** no exported function or
   method mutates an existing persona (reflection/API-surface test proves the
   absence of the path, type-level).
3. **Given** a daemon restart, **When** personas load from disk, **Then** each
   re-binds to the same cast id it was generated for (card AC #4) and loading
   is read-only.

### User Story 3 - Drift dies at a gate with no model in it (Priority: P1)

As an operator, I want persona drift rejected by arithmetic, not by another
model call, so that rejection is a testable 100% guarantee.

**Independent Test**: Card AC #3 — the validator rejects a drifted persona
with zero LLM involvement: anchor echo (verbatim restatement under
normalization) and drift lexicon (word-boundary, case-insensitive).

**Acceptance Scenarios**:

1. **Given** a text that fails to restate the persona's anchor line verbatim
   (under whitespace/case normalization), **Then** the validator rejects it.
2. **Given** a text containing any of the persona's drift-marker words at a
   word boundary, any case, **Then** the validator rejects it.
3. **Given** a conforming text, **Then** the validator accepts it, and no code
   path in the validator can issue a model call (no `llm` import in the
   validator's package — provable structurally).

### User Story 4 - No moralizer is born (Priority: P2)

As a player, I want no villager whose generated character is "corrects the
player's manners", so that the politeness-policing spell-breaker cannot ship
at birth.

**Independent Test**: Card AC #6 — the genesis prompt contains no moralizing
persona template (named prompt-content test), and the authored moralizing
lexicon (cast-wide, part of the drift lexicon) rejects a persona/consolidation
that states moralizing traits.

**Acceptance Scenarios**:

1. **Given** the E1 prompt text, **Then** a named test asserts it instructs
   away from moralizing/manner-policing characters.
2. **Given** a text stating a moralizing trait (e.g. "scolds", "corrects
   manners", "lectures"), **Then** the validator rejects it for every persona
   (the moralizing lexicon is cast-wide, authored, not generated).

## Requirements *(mandatory)*

- **FR-001**: A `mind/persona` package owns genesis, storage, load/re-bind,
  and validation. It ports promptworld I's two-half design; it imports the
  `llm` client only in the genesis half — the validator half imports no LLM
  code (structural guarantee for AC #3).
- **FR-002**: Genesis: for each of three cast entries, one E1 call (Opus 5 per
  the existing `llm.E1` class config; not cached; pre-session; unbounded
  latency) producing structured output: name, values, endogenous desires,
  anchor line, drift markers, plus the profession/biome pairing carried
  through. Three calls total — no retries that silently multiply spend beyond
  the client's existing retry policy.
- **FR-003**: Storage: one file per persona, written exactly once at mode
  0444; the package exposes no exported mutation path post-genesis; re-running
  genesis with existing files is a refused no-op, not a regenerate.
- **FR-004**: Restart/re-bind: loading reads persona files and binds each to
  its cast id; a persona for an unknown cast id or a cast id with no persona
  is a startup error, not a silent regenerate.
- **FR-005**: Validator: model-free; anchor echo under normalization + drift
  lexicon (per-persona generated markers ∪ authored cast-wide moralizing
  lexicon), word-boundary and case-insensitive; returns reject-with-reason.
- **FR-006**: The honest limit is recorded in code comment and wiki: the
  lexicon catches *stated* drift; subtle drift detection is parked (model-
  judged validator, post-demo).
- **FR-007**: Live proof: genesis runs once for real against the API (key via
  root `.env`), producing three 0444 persona files; the run's output is the
  restart/re-bind proof's input. Unit tests mock the client (M4 idiom);
  the live run is recorded in the PR description.
